# Парные горизонты и ограничение сложности: отдельная проверка

Протокол фиксируется после отрицательного результата критерия log loss на первой когорте MovieLens 1M и до оценки следующей когорты. Первая когорта `user % 6 == 0` служит разработке гипотезы; новая проверка использует ранее не оценённых пользователей `user % 6 == 1`, сохраняя все их взаимодействия.

Гипотеза: выбранный короткий временной агрегат полезно сопровождать агрегатом всей истории той же сущности. Такая пара сохраняет долгосрочную опору при временном сдвиге. Предложение пакета автоматически включает доступные непостоянные столбцы его all-history аналога. Вручную выбранная сущность в стартовую модель не добавляется; стартовыми остаются статические признаки.

Дополнительно число столбцов ограничено `floor(0.6 * feature_count_manual)` по train-описанию ручного baseline. Пакеты, превышающие остаточный бюджет, исключаются до обучения. Восемь раундов по три предложения дают максимум 24 проверки на стратегию/seed; при исчерпании допустимых пакетов поиск заканчивается раньше. Фактический бюджет и все попытки публикуются. Random и residual получают одинаковые правила включения all-history и ограничения сложности.

Сущности, окна, сглаживание, временное разбиение 65/15/20%, сетка CatBoost, seed 17/42/73 и one-hot порог 65535 сохраняются. Гиперпараметры заново выбираются только на validation новой когорты. Агрегаты рассчитываются только по ней, поэтому метки предыдущей когорты исключены из новых признаков.

Основной критерий: верхняя граница парного пользовательского 95%-интервала прироста средней по seed потери относительно ручного baseline <0.01. Компактность обеспечивается ограничением архитектуры, а качество проверяется на новом test. Порог 0.01 сохраняется из предыдущего протокола. Ранжирование каталога остаётся отдельной оценкой.

Это пользовательская репликация в той же платформе и эпохе. Объекты и календарный период общие; независимость от предыдущего исследования относится к меткам выбранных пользователей и данным для расчёта истории. Полная междоменная проверка остаётся дальнейшей задачей.

# Протокол эксперимента

Зафиксирован до получения тестовых результатов.

## Гипотеза

Автоматический поиск по грамматике исторических агрегатов может находить полезные сочетания сущностей и временных окон. Направление поиска по корреляции кандидатов с остатками текущей модели может эффективнее использовать ограниченный бюджет переобучений.

## Данные и задача

MovieLens 100K: все 100 000 оценок, `label = int(rating >= 4)`. Объекты имеют несколько жанров, поэтому пользовательско-жанровые признаки должны учитывать каждый жанр фильма. Демографические признаки пользователей и жанры считаются статическими; даты релиза используются только как статические метаданные.

Вероятность положительной оценки оценивается на наблюдаемых оценках. Отсутствие взаимодействия имеет неизвестную метку. Ранжирование проводится внутри наблюдаемого набора фильмов пользователя в тестовом периоде, с явным указанием ограничений этой оценки.

## Разбиение

Два expanding-window разбиения: train/validation/test = 0–50% / 50–65% / 65–80% и 0–65% / 65–80% / 80–100% хронологически упорядоченных событий. Граница всегда проходит между различными timestamp. Тестовые периоды разделены. Второе разбиение использует более позднюю обучающую историю.

Каждый timestamp обрабатывается атомарно: события с тем же временем исключаются из истории. История обновляется после поступления фактического отклика; при оценке это предполагает немедленную доступность прошлых оценок. Параметры моделей и выбор признаков используют только train и validation. Финальная модель переобучается на train+validation с числом деревьев, выбранным на validation; test используется для итогового сравнения.

## Сравнения

1. Сглаженная историческая положительность фильма.
2. CatBoost со статическими признаками.
3. CatBoost с ручными признаками: сущности user, item, user×genre, genre, user×item; окна 7/30/90 дней и вся история.
4. Ручные признаки + случайный последовательный поиск пакетов.
5. Ручные признаки + последовательный поиск, направляемый остатками.
6. Все доступные пакеты как контроль эффекта отбора.

У поиска одинаковые число раундов, число проверяемых предложений, гиперпараметры, seed и критерий принятия. Направляемый метод дополнительно затрачивает время на скоринг кандидатов; оно измеряется отдельно. Общий тюнинг базового бустинга проводится по небольшой заранее заданной сетке. Выбор дополнительных признаков минимизирует validation log loss.

## Оценка

Log loss — основная метрика. ROC AUC, Brier score, NDCG@10, Recall@10 — дополнительные. Ранжирование усредняется по пользователям с минимум двумя наблюдениями и обеими метками в соответствующем периоде. Cold-start сегменты выделяются по истории до начала test. Для выбранных сравнений рассчитываются парные bootstrap-интервалы с ресемплированием пользователей.

Три фиксированных seed: 17, 42, 73. Два временных разбиения. Сохраняются все попытки поиска, длительность обучения, наборы признаков и конфигурации. Интервалы характеризуют неопределённость на данных теста; устойчивость к seed и временному сдвигу оценивается отдельно.

## Критерии успеха и ограничения

Успех автоматизации — исполняемый поиск с причинно корректными признаками и воспроизводимым сравнением. Превосходство направляемого поиска над случайным требует согласованных результатов на отложенных периодах. Результаты с ухудшением качества также публикуются. Число пользователей невелико, оценки селективны, признаки рассчитываются по доступному каталогу; выводы о промышленном CTR и причинном эффекте рекомендаций требуют дополнительных данных и онлайн-проверки.
